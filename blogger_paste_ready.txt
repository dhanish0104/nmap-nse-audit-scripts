<h2>Intro to Nmap</h2>
<p>Network Mapper (<strong>Nmap</strong>) is an open-source tool for network discovery, host enumeration, and security auditing. It allows system administrators and security researchers to discover active hosts across a network, identify open TCP and UDP ports, detect running services and version numbers, and determine underlying operating systems.</p>
<p>Nmap includes the <strong>Nmap Scripting Engine (NSE)</strong>, which executes automation scripts written in the <strong>Lua</strong> programming language. NSE allows users to extend Nmap's core functionality beyond standard port scanning into vulnerability verification, advanced discovery, and network compliance checks. While standard Nmap scripts collect raw banners and output from services, custom NSE scripts can actively analyze protocol replies in real time and evaluate whether the target service violates security best practices.</p>

<h2>Nmap reference script1 description</h2>
<p>The stock Nmap script <code>smtp-commands.nse</code> (authored by Jasey DePriest) connects to an SMTP service on standard mail ports (25, 465, or 587). It initiates an application-layer handshake by sending the <code>EHLO</code> command with the local domain to gather Extended SMTP (ESMTP) keywords advertised by the server. It then issues a <code>HELP</code> command to retrieve additional supported commands.</p>
<p>The script strips SMTP response codes (<code>250-</code>, <code>214-</code>) using Lua string substitutions, trims extra whitespace, and formats the output into a single comma-separated list of supported commands.</p>
<p><strong>Limitation:</strong> The reference script functions strictly as an informational discovery tool. It reports the raw commands supported by the target server without evaluating whether any of those commands introduce a security risk or whether critical protection mechanisms (such as transport encryption) are missing.</p>

<h2>Nmap reference script2 description</h2>
<p>The stock Nmap script <code>ftp-anon.nse</code> (authored by Eddie Bell, Rob Nicholls, Ange Gutek, and David Fifield) connects to an FTP service on ports 21 or 990. It attempts an unauthenticated login using the credentials <code>anonymous:IEUser@</code>. </p>
<p>If the server grants anonymous access (FTP return code <code>230</code>), the script establishes a passive data connection via <code>PASV</code> and issues a <code>LIST</code> command to retrieve a directory listing of the root directory. It examines the file permissions column of each entry using Lua pattern matching (<code>^[d-].......w.</code>) and tags entries that have world-writeable permissions with <code>[NSE: writeable]</code>.</p>
<p><strong>Limitation:</strong> While the reference script flags writeable file system permissions, it performs no analysis on the filenames themselves. High-risk confidential assets—such as <code>.env</code> configuration files, <code>id_rsa</code> private keys, <code>backup.zip</code> archives, and <code>passwd</code> files—are displayed without any security warnings or prioritization.</p>

<h2>Nmap reference script1 enhancement options 1 and 2</h2>
<p>To transform these base scripts into active security evaluation tools, two distinct enhancement options were developed:</p>
<h3>Enhancement Option 1: Automated SMTP Security Risk Assessment (<code>smtp-risk-check.nse</code>)</h3>
<ol>
<li><strong>User Enumeration Detection:</strong> Inspect the combined <code>EHLO</code> and <code>HELP</code> responses for the presence of the <code>VRFY</code> (Verify) and <code>EXPN</code> (Expand) commands. If advertised by the server, flag the finding with:<br />
<code>[!] User enumeration possible via VRFY/EXPN</code></li>
<li><strong>Missing Encryption Warning:</strong> Verify whether the server advertises <code>STARTTLS</code>. If missing, output a security alert:<br />
<code>[!] STARTTLS not advertised -- mail may be sent/received unencrypted</code></li>
<li><strong>Preserved Core Compatibility:</strong> Retain the socket handling of <code>go()</code> while adding a dedicated evaluation function <code>check_risks()</code> to append findings beneath the command list.</li>
</ol>
<h3>Enhancement Option 2: Automated Sensitive File Detection in Anonymous FTP (<code>ftp-anon-plus.nse</code>)</h3>
<ol>
<li><strong>Sensitive Filename Pattern Matching:</strong> Extend anonymous FTP directory listing parsing with a regular expression pattern table (<code>SENSITIVE_PATTERNS</code>) targeting configuration secrets, private keys, backups, and user databases (e.g., <code>.env</code>, <code>id_rsa</code>, <code>backup.zip</code>, <code>config</code>, <code>passwd</code>).</li>
<li><strong>Inline File Tagging:</strong> Mark matched files with <code>[NSE: sensitive]</code> alongside standard <code>[NSE: writeable]</code> permissions tags.</li>
<li><strong>Findings Summary Footer:</strong> Append a consolidated summary line:<br />
<code>Sensitive files detected: &lt;list of files&gt;</code></li>
</ol>

<h2>Nmap newly generated script with enhancement option1 description</h2>
<p>The enhanced script <code>smtp-risk-check.nse</code> builds upon <code>smtp-commands.nse</code> by adding an active security evaluation layer:</p>
<ol>
<li><strong><code>check_risks(combined_text)</code> Function:</strong> Inspects the combined text returned from both <code>EHLO</code> and <code>HELP</code>:</li>
<li>Scans for <code>VRFY</code> and <code>EXPN</code>. These commands allow unauthenticated clients to verify whether usernames exist on the mail server. When detected, the script flags a potential user enumeration vector.</li>
<li>Scans for <code>STARTTLS</code>. In the absence of <code>STARTTLS</code>, mail is transmitted in cleartext over port 25, vulnerable to interception. If <code>STARTTLS</code> is missing, the script flags an unencrypted transmission risk.</li>
<li><strong>Action Pipeline Integration:</strong> The main <code>action</code> function executes <code>go()</code> to retrieve supported commands, combines the output into a single string, evaluates it through <code>check_risks()</code>, and appends the warning flags directly underneath the supported commands list.</li>
</ol>

<h2>Nmap newly generated script with enhancement option2 description</h2>
<p>The newly generated script <code>ftp-anon-plus.nse</code> enhances <code>ftp-anon.nse</code> by adding automated sensitive filename detection:</p>
<ol>
<li><strong><code>get_entry_name(item)</code>:</strong> Parses standard UNIX <code>LIST</code> directory responses using the regex <code>([^%s]+)$</code> to extract the filename from each entry.</li>
<li><strong><code>SENSITIVE_PATTERNS</code> Dictionary:</strong> Defines 16 regex patterns targeting high-value files:</li>
<li>Environment files: <code>^%.env$</code>, <code>^%.env%.</code></li>
<li>SSH and cryptographic credentials: <code>^id_rsa</code>, <code>^id_dsa</code>, <code>^%.ssh$</code></li>
<li>Web &amp; server configs: <code>^%.htaccess$</code>, <code>^config$</code></li>
<li>User database files: <code>^passwd$</code>, <code>^shadow$</code></li>
<li>Backups and database archives: <code>^backup</code>, <code>^database</code>, <code>^secret</code>, <code>^token</code>, <code>^private</code></li>
<li><strong><code>is_sensitive(name)</code> Function:</strong> Performs case-insensitive matching against each pattern in the dictionary.</li>
<li><strong>Tagging and Summarizing:</strong> Checks each directory entry for write permissions (adding <code>[NSE: writeable]</code>) and sensitive filename patterns (adding <code>[NSE: sensitive]</code>). If sensitive files are detected, appends a summary footer:<br />
<code>Sensitive files detected: &lt;list of files&gt;</code></li>
</ol>

<h2>Learning outcomes</h2>
<ol>
<li><strong>Nmap Scripting Engine (NSE) Mechanics:</strong> Gained hands-on experience developing Lua scripts for Nmap, leveraging <code>portrule</code> conditional triggers, socket management through <code>nmap</code>, and formatting with <code>stdnse</code>.</li>
<li><strong>Application-Layer Protocol Analysis:</strong> Explored the operational mechanics of SMTP (RFC 821/5321) greeting exchanges (<code>EHLO</code>, <code>HELP</code>), standard response status codes (<code>220</code>, <code>250</code>, <code>214</code>), and transport layer security upgrades via <code>STARTTLS</code>.</li>
<li><strong>Identification of Information Disclosure Vectors:</strong> Learned how legacy mail commands (<code>VRFY</code>, <code>EXPN</code>) facilitate user enumeration, and how anonymous FTP services expose critical assets when file naming conventions are not audited.</li>
<li><strong>Pattern-Matching Implementation:</strong> Developed regex-based classification logic in Lua to parse unstructured directory listings and detect sensitive files during active scans.</li>
<li><strong>Practical Reconnaissance Debugging:</strong> Solved real-world scanning obstacles on Windows, including firewall ping filtering (bypassed with <code>-Pn</code>), socket address collisions (<code>taskkill</code>), and silent authentication rejections (FTP code <code>530</code>).</li>
</ol>

<h2>Conclusion</h2>
<p>Extending Nmap's base scripts in Lua demonstrates how network scanning can be elevated into automated security risk evaluation. By adding lightweight pattern matching and protocol verification logic, the two enhanced scripts transform passive banner and directory data into immediate, actionable security findings without requiring complex third-party vulnerability scanners. This project highlights the practical value of script extensibility in network security workflows.</p>
